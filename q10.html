Implement Information Extraction Solutions Question 10: Grounding a Field to Its Source Location

Case Study: Meridian Outfitters - RangerOps Project

Meridian Outfitters is an outdoor-gear manufacturer and retailer that uses Microsoft Foundry to run a project named RangerOps. The project contains multiple agents that support customer service, vendor invoice reconciliation, and warranty processing.

  • Meridian uses Microsoft Entra ID for identity. Two security groups exist: SC_RangerOps_Dev (the RangerDev engineering team) and SC_RangerOps_Test (the RangerTest validation team).
  • An agent named Ranger1 answers customer product questions. It currently uses a base model deployment with no content-safety pipeline, no tool-approval workflow, and no conversation-memory configuration.
  • A second agent, InvoiceBot, is planned to reconcile vendor invoices against contract terms. Invoices arrive as scanned PDFs from many vendors, with varied layouts, embedded tables, company logos, and occasional handwritten annotations.
  • Product data sheets are stored as PDFs in an Azure Blob Storage account named storage1 and are not yet indexed for retrieval.
  • All agents in RangerOps are intended to share a single Azure AI Search resource for retrieval.
  • Deploy InvoiceBot using Azure AI Content Understanding to extract structured data from scanned vendor invoices, including a vendor name, invoice number, total amount, a document category, and a generated risk summary, directly from documents that include tables and logos.
  • Configure confidence-based routing so that only high-confidence invoice fields are auto-approved, and lower-confidence fields are routed to a human reviewer.
  • Enable Ranger1 to retrieve grounded answers from the indexed product data sheets in storage1.
  • Give Ranger1 the ability to recall relevant details from a customer's previous conversations.
  • The model deployment used by Ranger1 must scale automatically to handle variable customer traffic without requiring reserved throughput capacity.
  • The model version used by Ranger1 must not change automatically; any version change must be an explicit action taken by the engineering team.
  • Azure AI Search credentials must be centrally managed at the project level and reusable by every agent in RangerOps, without duplicating credentials per agent.
  • InvoiceBot's extraction schema must explicitly define, for each field, whether the value is extracted verbatim from the document, classified from a fixed set of categories, or generated/inferred by the model.
  • Fields that are critical to financial approval must use stricter confidence thresholds than descriptive or comment fields.
  • When InvoiceBot encounters a new vendor invoice format that produces lower-than-expected confidence scores, the team must be able to improve extraction results without retraining a model from scratch.
  • API keys must NOT be used to access Foundry-deployed models or the Azure AI Search resource.
  • Access to the RangerOps project must be assigned to RangerDev and RangerTest members by using the existing security groups.
  • Ranger1 must be protected against malicious instructions that could be hidden inside images embedded in the product data sheets.
  • Ranger1 must answer questions only about Meridian products, and must not act as a general-purpose assistant.
  • Actions that Ranger1's tools take that could have a significant business impact must not execute without review.
  • Customers must experience continuity across sessions with Ranger1, including recall of relevant details from earlier conversations.
  • Financial approval workflows for invoices must minimize manual review while maintaining accuracy for high-value fields.

For the ContractReferenceNumber field, the finance team wants the analyzer result to include the exact bounding-box location in the source PDF where the value was found, so a reviewer can jump straight to it. Which extraction method should this field use?
